# RideLink - Driver & Vehicle Service

This is the Driver & Vehicle Service for the "RideLink" microservices-based ride-hailing system. This service manages driver operational profiles, vehicle management, and availability states.

## Member 2 Responsibilities
This project covers Member 2's responsibilities:
- Driver Operational Profile Management
- Vehicle Management
- Driver Availability Status
- Simulated Current Location Updates
- Service Area Management
- Eligible Driver Retrieval

This service is a backend-only REST API. It does NOT handle account registration or authentication directly. Authentication is owned by the Account Service.

## Technology Stack
- Java 21
- Spring Boot 4.1.1
- Maven
- Spring Web MVC
- Spring Data MongoDB
- Spring Security (JWT processing)
- Bean Validation
- OpenAPI / Swagger (springdoc)
- JUnit & Mockito

## Prerequisites
- Java 21 installed (`java -version`)
- Maven installed (or use provided `./mvnw` wrapper)
- MongoDB running on `localhost:27017`

## Project Structure
The project follows a layered architecture:
```
com.ridelink.drivervehicleservice
├── controller     (REST APIs)
├── dto            (Data Transfer Objects)
├── exception      (Global exception handling)
├── model          (MongoDB Entities)
├── repository     (Spring Data repositories)
├── security       (JWT parsing and validation)
├── service        (Business logic)
└── DriverVehicleServiceApplication.java
```

## Microservice Boundary & Integration Notes
- This service does NOT directly connect to the `ridelink_account_db`.
- It references `accountId` as an external string field.
- Integration between the Account Service and this service must happen via REST APIs (e.g., passing the `accountId` securely).

## Environment Variables
The application uses a `.env` file for environment variables. A template is provided in the project root.
Create a `.env` file (if not already present) in the root directory:
```env
MONGO_URI=mongodb+srv://<username>:<password>@cluster0.example.mongodb.net/ridelink_driver_vehicle_db?appName=Cluster0
JWT_SECRET=your_jwt_secret_key_here
```
Note: Replace `<username>` and `<password>` with your actual MongoDB credentials and `your_jwt_secret_key_here` with the shared JWT secret.

## How to Run
Start your MongoDB cluster (already hosted on Atlas).

Run the Spring Boot application:
```bash
./mvnw clean spring-boot:run
```
The application will automatically load the `.env` variables and start on port `8082`.

## How to Run Tests
```bash
./mvnw clean test
```
The tests use JUnit and Mockito to verify service layer logic.

## JWT / Security Explanation
This service requires a valid Bearer JWT to access its endpoints.
The token must be passed in the `Authorization` header:
`Authorization: Bearer <token>`
The `JwtAuthenticationFilter` validates the signature using the configured `JWT_SECRET`. It does NOT attempt to hit a database to verify the user, keeping authentication strictly stateless and delegated to the Account Service.

## Postman Testing Workflow
Use `http://localhost:8081` as the base URL. Ensure you set the `Authorization` header with `Bearer <token>` for all endpoints.

1. **Create Driver Profile**: `POST /api/drivers`
2. **Get Driver Profile**: `GET /api/drivers/{id}`
3. **Update Driver Profile**: `PUT /api/drivers/{id}`
4. **Update Availability**: `PUT /api/drivers/{id}/availability` (Body: `{"status": "AVAILABLE"}`)
5. **Update Service Area**: `PUT /api/drivers/{id}/service-area` (Body: `{"city": "Colombo", "district": "Colombo"}`)
6. **Update Current Location**: `PUT /api/drivers/{id}/location` (Body: `{"latitude": 6.92, "longitude": 79.86}`)
7. **Add Vehicle**: `POST /api/drivers/{driverId}/vehicles`
8. **Get Driver Vehicles**: `GET /api/drivers/{driverId}/vehicles`
9. **Update Vehicle**: `PUT /api/vehicles/{vehicleId}`
10. **Get Eligible Drivers**: `GET /api/drivers/eligible?city=Colombo`
